**Code (context)**

```js
const notifyAdded = useCallback((productName) => {
  const name = String(productName || "").trim();
  setAddedNotice(name ? `${name} was added to the cart.` : "Item was added to the cart.");
}, []);

useEffect(() => {
  if (!addedNotice) return undefined;
  const timer = window.setTimeout(() => setAddedNotice(""), 5000);
  return () => window.clearTimeout(timer);
}, [addedNotice]);
```

**Code (call site after a successful add)**

```js
await refreshCart();
if (nextQuantity > (line?.quantity ?? 0)) notifyAdded(product.product_name);
```

Shared pieces:

| Component | Use |
| --- | --- |
| `LoadingState` | Spinner + label while data loads |
| `ErrorState` | Title + message + **Try again** |
| `EmptyState` | Empty list (no products / no orders / empty cart) |
| `ErrorNote` | Short red note on a form that is already on screen |
| `describeLoadError(what, err)` | Builds titles like “Error fetching product data” |
| `describeActionError(action, err)` | Builds “Could not add to cart: …” |

**Workflow (products)**

```text
Open /products
  → LoadingState “Loading products...”
  → fetch succeeds → grid
  → fetch fails → ErrorState title “Error fetching product data”, Try again
  → clears old cards while loading or failed
```

**Code**

```js
export function describeLoadError(what, error) {
  const detail = error?.message || "Please try again.";
  if (error?.status === 404) return { title: `${what} not found`, message: detail };
  if (error?.status === 403) return { title: `Cannot load ${what.toLowerCase()}`, message: detail };
  return { title: `Error fetching ${what.toLowerCase()}`, message: detail };
}
```

```jsx
{!loaded && !error ? <LoadingState label="Loading products..." /> : null}
{error ? <ErrorState title={error.title} message={error.message} onRetry={retryLoad} /> : null}
```

`client.js` still maps dead connections and 502/503/504 to shopper-friendly messages.

## Backend

### 1. Circuit breaker transition logs

**File:** `app/integrations/circuit_breaker.py`

Every state change logs `event: "circuit_state"` with `transition: "previous -> next"`. Failures that stay closed log `circuit_failure` with `still closed`.

**Workflow**

```text
Card checkout / charge fails (provider fail/slow) — each checkout that hits the gateway counts once
  Fail 1 → circuit_failure, transition "closed -> closed"
  Fail 2 → circuit_failure, transition "closed -> closed"
  Fail 3 → circuit_state, transition "closed -> half-open"
  Fail 4 → circuit_state, transition "half-open -> open"
While open and provider still down → circuit_off, charge skipped
Provider mode ok → half-open probe; success → "half-open -> closed"
```

**Code**

```python
def _set_state(self, state: str, detail: str) -> None:
    previous = self.state
    self.state = state
    _log(
        "circuit_state",
        name=self.name,
        previous=previous,
        state=state,
        transition=f"{previous} -> {state}",
        failures=self.failures,
        detail=detail,
    )
```

**Example log lines**

```json
{"event":"circuit_failure","name":"payment","state":"closed","transition":"closed -> closed","failures":1,"detail":"payment failure 1 of 3, still closed"}
{"event":"circuit_state","name":"payment","previous":"closed","state":"half-open","transition":"closed -> half-open","failures":3}
{"event":"circuit_state","name":"payment","previous":"half-open","state":"open","transition":"half-open -> open","failures":4}
```

View with:

```bash
docker compose logs api | findstr circuit_
```

### 2. Payment notification logging

**Files:**  
`app/integrations/notification.py`  
`app/routers/order_router.py` (trigger `"checkout"`)  
`app/routers/ops_router.py` (trigger `"payment_retry"` or `"manual"`)

Still runs in `BackgroundTasks` after checkout and after pay again. Every line has `"kind":"notification"`.

**Workflow**

```text
POST /api/orders/checkout  (or POST /api/payments/process)
  → order saved / payment result written
  → response returned to the browser
  → background: send_order_notification(..., trigger)
       → notification_started
       → POST NOTIFY_API_URL (provider /notify) with retries
       → notification_sent   OR   notification_failed
```

**Code**

```python
def _log(event: str, **fields) -> None:
    log_event(event, kind="notification", **fields)

async def send_order_notification(order_id, email, payment_status, trigger="checkout"):
    _log("notification_started", order_id=order_id, email=email,
         payment_status=payment_status, trigger=trigger, ...)
    # POST to NOTIFY_API_URL ...
    _log("notification_sent", ...)   # or notification_failed / notification_skipped
```

**Example log lines**

```json
{"event":"notification_started","kind":"notification","order_id":13,"email":"het@example.com","payment_status":"PAID","trigger":"checkout","detail":"payment notification queued"}
{"event":"notification_sent","kind":"notification","order_id":13,"email":"het@example.com","payment_status":"PAID","trigger":"checkout","detail":"payment notification delivered"}
```

COD still notifies with `"payment_status":"PENDING"`. Pay again uses `"trigger":"payment_retry"`.

```text

  → several card checkouts fail
  → circuit_failure then circuit_state transitions in logs
```
